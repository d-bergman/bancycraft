# In-app Windows updates

The repository and releases are public by explicit user choice. The installed app uses electron-updater's GitHub provider pinned to `d-bergman/bancycraft`, with stable releases only. `latest.yml` and `app-update.yml` are generated by electron-builder. No GitHub credentials ship in the app.

Settings offers Check for updates, Download update with percentage progress, and Restart & install after successful verification. Downloads and installation are explicit. The updater disallows downgrades and prereleases. Errors leave the local workspace available. Before installation, the app backs up the current workspace file. User data remains under `%APPDATA%/BancyCraft`, outside the installation directory.

The Windows executable currently has no purchased Authenticode certificate. Instead, update installation requires an additional detached Ed25519 signature over the installer's SHA-512 digest. The trusted public key is bundled at `electron/update-public.pem`; the private key stays outside the repository at `%LOCALAPPDATA%/BancyCraft-release-keys/update-signing.pem`, in a folder restricted to the Windows user and SYSTEM. electron-updater verifies the manifest SHA-512 first and invokes our signature verifier before declaring an update ready. The signature is downloaded anonymously from the fixed release's installer `.sig` asset. Altered files and untrusted keys are rejected. Preserve and privately back up this key before moving development to another computer; never generate a replacement for existing users without a migration release.

## Release procedure

1. Complete the implementation, tests and documentation. Bump the version with `npm.cmd version patch --no-git-tag-version`.
2. Run `npm.cmd run dist`; it never publishes automatically.
3. Run native and packaged smoke tests, including `node scripts/lists-smoke.cjs release/win-unpacked/BancyCraft.exe`.
4. Run `node scripts/releases.cjs sign <version>` and verify the signature locally.
5. Commit and push the tested source, then run `node scripts/releases.cjs draft <version>`. This creates a draft with the installer, blockmap, detached signature and latest.yml. Review its contents.
6. Run `node scripts/releases.cjs publish <version>` only for the authorized release. Clients can then discover it. Test a live check and download with the real updater before claiming distribution works.

The release tool obtains GitHub credentials from the configured git credential manager in process memory. It does not log, persist or package the token. Published installers are immutable; do not overwrite a version. Back up user data before attempting a manual rollback to schema 1.

## Bootstrap

Version 0.2.0 and earlier have no connected feed and cannot discover this update themselves. Install the current release once over the existing installation. From 0.3.0 onward, use Settings. The updater launches the NSIS installer silently and restarts the app after the user clicks Restart & install.

Development/browser previews do not install updates. Real online check/download testing uses an isolated profile and an older updater version to exercise a newly published release. That test does not silently overwrite the user's existing installed application.

Run `node scripts/updates-smoke.cjs release/win-unpacked/BancyCraft.exe` after publishing the current release to exercise the public check, download, signature and ready state. The test reads the current package version and simulates 0.3.0 for this release. Adapt the simulated version for subsequent releases. An unpublished draft can be discarded with `node scripts/releases.cjs discard-draft <version>` if a rebuilt installer is necessary; this command refuses to modify published releases.
